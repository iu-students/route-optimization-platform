# Sprint Retrospective

## What went well
1. **Successful release of the first MVP version:** The team successfully implemented the core algorithmic logic, using PyVRP for vehicle routing and a greedy algorithm for loader distribution.
2. **Access via public IP address:** The team prepared the working environment and forwarded ports so the customer could interact with the developed features in real-time, not just locally.
3. **Constructive feedback exchange with the customer:** The team effectively presented the UI choice (Swagger UI) and the updated backlog, receiving clear and practical feedback from the customer regarding business constraints and architectural improvements.

## What did not go well
1. **Lack of exact testing metrics:** During the meeting, the team could not provide exact statistics on how the algorithm performs against the baseline across all test cases, making it difficult to evaluate the true success rate of the project.
2. **Unstructured links in the chat with the customer:** Links to repositories and artifacts were sent chaotically. Because of outdated links, the customer could not find the actual repository and necessary branches, which slowed down the code review process.
3. **Incomplete business logic in the backlog:** The team missed adding user stories for optional and mandatory orders, as well as manager metrics, until the customer explicitly pointed them out during the review.

## Action points
1. **Implement a pre-meeting preparation checklist:** Before any review with the customer, the team must run all required tests, collect exact quantitative metrics (e.g., baseline comparison percentages), verify all links.
2. **Conduct internal backlog refinement:** Before presenting user stories to the customer, hold an internal review session to check the backlog against core business requirements. This will help identify and add missing constraints or critical metrics early, avoiding gaps in requirements.
3. **Structure links in the customer chat:** Keep a clean, updated list of all relevant project links (repository, active branches, server IP) in the chat. Remove or clearly mark outdated links so the customer can easily find the right resources.
